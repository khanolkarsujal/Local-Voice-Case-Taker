# VOICECASE AI — COMPLETE PRODUCT REDESIGN + FEATURE IMPLEMENTATION

You are working on an EXISTING VoiceCase AI project.

Do NOT blindly rebuild the application from scratch.

First inspect the existing codebase, understand the current architecture, identify what already works, and then improve it.

The goal is to transform the existing project into a **polished, hospital-grade healthcare SaaS prototype** suitable for:

* Smart India Hackathon / hackathons

The most important priorities are:

---

# 1. CORE PRODUCT

Product name:

**VoiceCase AI**

Tagline:

**"Let the patient tell their story before they enter the consultation room."**

VoiceCase AI is a multilingual voice-based patient case-taking assistant.

It collects structured medical history before consultation by:

PATIENT
↓
VOICE INTERVIEW
↓
SPEECH-TO-TEXT
↓
STRUCTURED QUESTIONS
↓
ANSWER PROCESSING
↓
CASE HISTORY
↓
DOCTOR REVIEW

It is NOT an AI doctor.

The system must never:

* Diagnose
* Prescribe medication
* Recommend treatment
* Provide medical conclusions
* Replace a healthcare professional

The system is only for information collection and documentation.

Prefer a clean modern stack.

## Frontend

React + TypeScript

Prefer:

* Vite
* Tailwind CSS
* shadcn/ui or similarly clean component system
* Lucide icons
* React Router
* TanStack Query where useful

* excessive dependencies
* unnecessary animation libraries

Python + FastAPI

Use clear separation:

API
→ Services
→ Business logic
→ Database

For prototype:

## AI

* response understanding
* structured extraction
* approved follow-up selection
* case-summary transformation

It must NEVER generate arbitrary medical questioning.

# 13. QUESTION ENGINE

Questions must be deterministic.

Create a structured question configuration.

Categories:

PATIENT INFORMATION

1. What is your name?
2. What is your age?
3. What is your gender?

CHIEF COMPLAINT

4. What is the main health problem you are experiencing?
5. When did this problem start?
6. Where exactly are you experiencing the problem?
7. How severe is it from 1 to 10?
8. Is the problem constant or does it come and go?
9. What makes it better or worse?
10. Are you experiencing any other symptoms?

MEDICAL HISTORY

11. Do you have any existing medical conditions?
12. Are you currently taking any medicines?
13. Do you have any known allergies?
14. Have you had any previous surgeries or major medical problems?

RELEVANT HISTORY

15. Have you experienced this problem before?
16. Is there anything else about your health that you think the doctor should know?

Store each question with:

* id
* category
* text
* language
* answer type
* required/optional
* approved follow-ups

---

# 15. FOLLOW-UP SYSTEM

Follow-ups are allowed ONLY when useful.

Create an approved follow-up question bank.

The LLM can select from this bank.

The LLM must NOT create new medical questions.

Example:

Patient:

"I have stomach pain."

Approved follow-up:

"Can you tell me where exactly the pain is located?"

The model may select that question.

It cannot invent:

"Does the pain indicate appendicitis?"

Never allow diagnostic questioning.

---

# 16. SAFETY LAYER

Create a separate safety service.

If a patient response contains a potentially urgent situation, do NOT diagnose.

Display:

**"Please seek immediate assistance from a healthcare professional."**

The system must not state:

"You may have..."

"This sounds like..."

"You should take..."

"This is safe..."

"This is dangerous..."

Keep all clinical decision-making with the doctor.

---

# 17. SPEECH-TO-TEXT ARCHITECTURE

Create a modular SpeechService.

Example abstraction:

SpeechService

Methods:

startListening()

stopListening()

transcribe()

isListening()

getTranscript()

This allows the STT provider to be replaced later.

Do NOT tightly couple the UI to one speech provider.

Handle:

* microphone permission
* silence
* bad audio
* empty transcript
* network errors
* provider errors
* retry
